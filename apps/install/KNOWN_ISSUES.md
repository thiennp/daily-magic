# Install Known Issues

- **d5e39215 / dd5c338d**: Fixed `run.sh` hard-coding `AGENT_WITCH_PROFILE` at install time (per-account hosts logged into the wrong profile). `run.sh` is profile-agnostic and repaired on host start; a mismatched account host exits once so launchd relaunches it. Migration lines go to `logs/host-services-migration.log`. Stale `host-services-migration.lock` files are cleared when the holder is gone. After migration, the legacy `com.agent-witch` LaunchAgent is rewritten as `/usr/bin/true` with RunAtLoad/KeepAlive off and booted out (not `launchctl disable`, so reinstall can still bootstrap it). Ships in bundle 312. The legacy launcher process no longer stops account hosts on SIGTERM.

- **5e000feb**: Linux install without a systemd user session used to print "AgentWitch is ready." while nothing was running. Finish now prints that it is installed but not running, the `nohup …/run.sh` start command, and the device name + id (with the same ·XXXX suffix the web app uses for duplicate names).
- **2331ef53**: Bundle updates on Linux no longer create `~/Library/LaunchAgents` (the plist ensure is macOS-only). A connect script that fails after setup began prints a re-run hint. Ships in bundle 317.
