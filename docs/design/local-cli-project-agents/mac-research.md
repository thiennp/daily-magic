# Local CLIs as project agents: AWL / codebase research (AW Mac)

Status: **research only, no product code.** Product (NRG AgentWitch Product) owns the design. This note gives facts about AWL (AgentWitch Local, the agent/app on the owner's computer) and the codebase.
Base: `origin/main` @ `199e1a8c` (read-only). Branch `docs/awl-local-cli-research`. Written 2026-10-06 (CEST).
Tags: **VERIFIED** = checked in official docs or in repo code at the cited line. **ASSUMED** = not confirmed. **PROPOSAL** = design suggestion, not built.

> **HARD SAFETY RULE (applies to everything below):** an AWL-launched CLI may run **only with its cwd inside a folder that is registered to the project for this device** (project folder ref / device binding). No ad-hoc cwd, no `os.tmpdir()`, no home dir. AWL must never print, log, upload or hash-and-send the **contents** of any credential/token/keypair/.env/auth file (`~/.claude*`, `~/.codex/auth.json`, `~/.gemini/oauth_creds.json`, `~/.cursor` tokens, `device-keypair.json`, `config.json` `pairingToken`, `writer-api-secrets.json`). Detection may use only **existence, path, mode** (and optionally a local-only sha256 fingerprint that never leaves the machine).

Prior art reused: `awl-setup-project-cli-write.md` (Arch r2 SHIP; referenced from `apps/live/features/token-saver/README.md:36` and `apps/live/features/token-saver/public-api/setupProject.types.ts:1`; the file itself is **not on origin/main**, it lives in the shared design folder `docs/design/token-saver-queue/` on the box). Its detect table said: Installed = `command -v claude`, `agent`/`cursor-agent`, `codex` (+ `--version`), never cat secret configs; D7 = `command -v …` **or** config dir exists. Gemini was not covered.

### 2.2 Folder registration / ACL

- **Tables:** `user_projects.device_id/folder_path` (`db/schema.sql:560-577`), `project_device_bindings(project_id, device_id, folder_path, folder_verified_at)` (`:579-591`), `project_folder_refs(project_id, machine_or_device_ref, folder_path)` (`:773-786`), computer seats `project_memberships.member_kind='computer'` + `device_id` (`db/migrations/068-project-membership-computer.sql:7-63`; one active seat per (project, device), `:60-63`).
- **Folder-ref write guard:** `checkFolderRefDeviceAcl` (`src/lib/projects/acl/checkFolderRefDeviceAcl.ts:20-44`). A deviceId target must be an active computer member of the project or the project's own live device. Legacy free-text labels pass through. `resolveFolderRefDeviceTarget` decides by the UUID shape (`resolveFolderRefDeviceTarget.ts:18-37`). Reads never call it.
- **Path validation:** `isValidProjectFolderPath` rejects only empty / `..` / NUL (`src/lib/projects/validateProjectFolderPath.ts:6-14`).
- **Gap (AWL side):** AWL **trusts `projectFolderPath` from the server**. It has no local allowlist and no realpath containment check, and `ensureAgentWitchProjectFolder` will `mkdir -p` any path it is given (`apps/live/features/projects/internal/core/ensureAgentWitchProjectFolder.ts:57-64`). The security rule ("only registered folders") is enforced **only server-side**.
- **Gap (seat path):** `dispatchProjectComputerAgentRun` sends `projectId` but **no `projectFolderPath`** and hard-codes `writerAgent: "claude-cli"` (`:60`, `:67`). By `resolveRunProjectFolderPath` that run would fail with "no folder on this computer yet" unless something else fills the folder in. **Verify** before building on the seat path; this is the natural hook for "CLI X on computer Y in project Z".

### 2.3 Permission posture today (risk)

All four writers run with approvals off: Claude `--dangerously-skip-permissions`, Codex `-s danger-full-access` (and a global `~/.codex/config.toml` `approval_policy="never"`), Cursor `--force --trust --sandbox disabled`, agy `--dangerously-skip-permissions`. The cwd is the project folder, but **nothing stops the CLI from touching files outside it**. "Only registered folders" is a cwd rule, not a sandbox.

## 4. Detect API surface for Team → Computers (**PROPOSAL**)

### 4.1 Local probe (AWL), no side effects

- Binary: resolve with a PATH walk using `fs.access(X_OK)` plus the configured `*Command` paths. Then **optionally** `<bin> --version` with a 3 s timeout (reuse `spawnForExit`, `probeLocalRunClis.ts:42-62`).
- Auth: **existence/presence only** by default (table §1.3). It may run the documented exit-code status commands (`claude auth status`, `codex login status`, `agent status --format json`) **only if Product accepts** that these run the CLI. Keep only the exit code / boolean, never stdout content beyond `loggedIn`/`isAuthenticated`. Gemini has no status command, so report `unknown`/`likely` from files plus env presence.
- Never: install, log in, change CLI config, send a prompt, or read token contents. That means **not** `runWriterEnsure` / `ensure-writer.sh`.
- Cache 10 min. Re-probe on demand.

```ts
// PROPOSAL — packages/shared/src/protocol (new)
export type LocalCliId = "claude" | "codex" | "cursor" | "gemini" | "antigravity";
export type LocalCliAuthState =
  | "signed_in"        // status command exit 0 (if allowed)
  | "signed_out"       // status command exit non-zero
  | "likely_signed_in" // binary + credential file/env present, no status command run
  | "unknown"          // binary present, no signal
  | "not_applicable";  // not installed
export interface LocalCliAuthSignal {
  readonly kind: "file" | "env" | "status_command";
  readonly ref: string;            // e.g. "~/.codex/auth.json", "GEMINI_API_KEY", "codex login status"
  readonly present: boolean;       // never the value
}
export interface LocalCliProbeEntry {
  readonly id: LocalCliId;
  readonly installed: boolean;
  readonly binaryPath: string | null;  // home-relative ("~/.local/bin/agent") to avoid leaking usernames
  readonly version: string | null;     // first line of --version, ≤64 chars, sanitized
  readonly authState: LocalCliAuthState;
  readonly authSignals: readonly LocalCliAuthSignal[];
  readonly headless: { readonly printFlag: string; readonly streamFormats: readonly ("json" | "stream-json" | "jsonl")[] };
  readonly lastChecked: string;        // ISO
  readonly probeMs: number;
}
export interface LocalCliProbeReport {
  readonly schemaVersion: 1;
  readonly deviceId: string;
  readonly platform: "mac" | "linux";
  readonly clis: readonly LocalCliProbeEntry[];
  readonly reportHash: string;         // sha256 of canonical clis[] (dedupe on server)
}
```

### 4.2 Transport

- Today there is **no capability channel**. `agent.heartbeat` (`startAgentWitchClient.ts:1168-1195`) carries hostname/user/wake/bundle version only. The server's `handleAgentHeartbeatMessageAsync` (`src/lib/agentWitch/handleAgentHeartbeatMessageAsync.ts:17-88`) uses it for lastSeen / device maintenance. `writer.status` reports one writer at a time and on request only (`handleWriterStatusMessageAsync.ts`). The closest precedent is **`harness.manifest.report`**, which is sent on connect (`startAgentWitchClient.ts:235-251, 1942`).
- **Proposal:** a new WS type `agent.capabilities.report` (add to `packages/shared/src/protocol/AgentWitchMessageType.constant.ts`). AWL sends it on `open` after `agent.register` (`:1926-1944`) and whenever `reportHash` changes. The heartbeat carries `capabilitiesHash` so the server can ask for a resend (`agent.capabilities.probe`, server→AWL). Only `role === "agent"` senders with a `deviceId` are accepted (same guard as `handleWriterStatusMessageAsync.ts:12-18`).

### 4.5 Security constraints

1. Registered-folder rule enforced **twice**: server (folder ref must belong to this device + project) **and AWL** (new: the realpath of cwd must equal a folder AWL has locally registered for that projectId. Reject otherwise and never `mkdir -p` an unknown path).
2. Probe sends booleans/paths/version strings only. No file contents, no env values, no token hashes off-device.
3. No install / login / config writes from detect. Login stays a human action in a terminal.
4. Toggle changes are owner-only and audited (reuse `writeProjectAccessAudit` / project activity events, migration 092).
5. Rate-limit refresh. The probe has a hard timeout (≤ 3 s per CLI, ≤ 10 s total).
6. Pick and document the approval posture per CLI (today all are full-permission, §2.3).

## 5. Optional local Ollama: pre-summarize README/docs before a paid call (**PROPOSAL**)

### 5.1 What exists

- **AWI installs Ollama automatically** when it is missing, on install and on self-update (brew, or a download into the install home), then pulls `qwen2.5:7b` + `nomic-embed-text` (`docs/qa/awi-does-not-install-local-llm.md`; `apps/install/features/self-update/internal/core/buildAgentWitchEnsureOllamaShell.ts:8-45`, `ensureAgentWitchOllamaInstalled.ts`). **This conflicts with "no forced install"**. Product/Lead should decide whether that stays.
- Existing probes: install shell `curl -fsS --max-time 2 http://127.0.0.1:11434/api/tags` (`buildAgentWitchEnsureOllamaShell.ts:9-11`). Runtime `ollama list` spawn, 3 s (`probeLocalRunClis.ts:64-116`). Base URL override `AGENT_WITCH_OLLAMA_URL`. Callers: `scripts/requestOllamaChat.ts:37-49` (`/api/chat`, `stream:false`, 120 s timeout), `scripts/requestOllamaEmbedding.ts:27-37` (15 s), `apps/live/features/knowledge/internal/core/agentWitchLocalRag.ts:68-97` (`/api/embeddings`, **deprecated**, **no timeout**).

### 5.2 Detection (described only; nothing was run on Thien's Mac)

1. Binary: PATH walk for `ollama` + known candidates (`~/.local/bin/ollama`, `~/.agent-witch/ollama/ollama`, `/opt/homebrew/bin/ollama`). Use `fs.access` only, no spawn.
2. Server: `GET {AGENT_WITCH_OLLAMA_URL||http://127.0.0.1:11434}/api/tags` with `AbortSignal.timeout(300)`. The response lists models (`name`, `digest`, `size`, `details.parameter_size`, `quantization_level`). VERIFIED ([openapi](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml)).
3. Pick a summary model already installed (reuse `selectInstalledOllamaEstimateModel`). If none is installed, **skip**. Never pull.
4. Cache the probe result for 60 s per process.

Endpoints (VERIFIED, Ollama docs): `GET /api/tags`. `POST /api/generate` `{model, prompt, stream:false, keep_alive}` (`keep_alive` default 5m, `0` unloads). `POST /api/chat`. `POST /api/embed` `{model, input: string|string[]}` → `embeddings[][]`. `/api/embeddings` (`prompt`) is **deprecated, superseded by `/api/embed`**. AWL's RAG should migrate to `/api/embed`.

### 5.3 Latency budget (PROPOSAL)

| Step | Budget | Otherwise |
| --- | --- | --- |
| Probe (`/api/tags`) | ≤ 300 ms | skip Ollama for this run |
| Summary per file | ≤ 8 s p95 (first call may include model load) | skip that file, send a truncated original |
| Total pre-LLM summarizing | ≤ 12 s, and never more than 20% of the task's estimate | stop, send what is ready |
| Input size | ≤ 32 KB per file (head+tail), ≤ 8 files | truncate |

No install prompt, no blocking dialog. A `capabilityNote`-style line ("Local summary skipped: Ollama not running") goes into the report.

### 5.4 Cache (PROPOSAL)

- Key: `sha256(fileBytes) + ":" + modelName + ":" + modelDigest + ":" + promptVersion`. The model digest comes from `/api/tags`, so a model update invalidates entries.
- Store: profile-scoped SQLite via the token-saver pattern: `loadNodeSqlite` (`apps/live/features/token-saver/internal/core/loadNodeSqlite.ts:27-76`, builtin `node:sqlite`, Node ≥ 22.13), `openPitfallDb` (`openPitfallDb.ts:36-48`: mkdir, `busy_timeout`, schema + version row), `resolveProfileScopedPath` (`resolveProfileScopedPath.ts:12-23`) → e.g. `~/.agent-witch/profiles/<email>/doc-summary-cache.db`, or per project under `project-data/<projectId>/` (§6). On Node < 22.13 the cache is off and summaries run uncached (same degrade as `describePitfallCacheAvailability`, `:79-84`).
- Table sketch: `doc_summary(cache_key TEXT PK, project_id TEXT, rel_path TEXT, bytes INT, summary TEXT, created_at TEXT, last_hit_at TEXT, hits INT)`. LRU cap: 2,000 rows or 20 MB per profile.

### 5.5 Privacy

- Only files whose realpath is inside a **registered project folder** for this device. Denylist: `.env*`, `*.pem`, `*.key`, `id_*`, `*credentials*`, `auth.json`, `.git/`, `node_modules/`.
- Content goes only to `127.0.0.1` (refuse a non-loopback `AGENT_WITCH_OLLAMA_URL` unless the owner sets it explicitly). Summaries stay local, in a 0600 file under a 0700 dir.
- Run `scrubProjectHistorySkillgenSecrets` on the summary before it is stored or sent to the paid LLM (§6.4).

## 6. Per-project local outcome store (same-machine fast path) (**PROPOSAL**)

Goal: after each task, keep a short prompt→outcome summary **on the machine that ran it**. Check it before calling the server or the LLM ("we did nearly this yesterday; here is what happened").

### 6.1 Where (reuse AW History layout)

- `resolveProjectDataDir(projectId)` → `<profileDir>/project-data/<projectId>/` (`apps/live/features/project-history/internal/core/resolveProjectDataDir.ts:19-29`). `ensureProjectDataTree` creates the tree with **0700** (`:31-43`; `ensureDir0700` in `atomicWriteFile0600.ts:9-12`; modes `PROJECT_HISTORY_DIR_MODE=0o700`, `FILE_MODE=0o600` in `projectHistoryPaths.constant.ts:8-9`).
- Proposed file: `<profileDir>/project-data/<projectId>/outcomes/outcomes.db` (0600).

### 6.2 Tie-in to History on/off + purge

- Write only when local History is on: `isLocalProjectHistoryOn(state)` (`isLocalProjectHistoryOn.ts:4-7`; states `off/on_configuring/on_ready/degraded`, server table `project_computer_history_settings`, `db/migrations/059-project-computer-history-settings.sql:7-14`; owner toggles via `toggleProjectComputerHistory`, events `owner_enable/owner_disable`).
- On History OFF, extend `purgeProjectHistoryOnOff` (`purgeProjectHistoryOnOff.ts:30-48`, today it removes `history/`, `skills/_drafts/`, `skillgen/`) to also remove `outcomes/`.
- **Owner-only delete:** a local AWL route (127.0.0.1, same uid, profile owner) `DELETE /api/local/projects/:projectId/outcomes[/:id]`, plus the server owner action that flips History off (which triggers the purge). Project members and other devices cannot read or delete it. It never leaves the machine unless the owner exports it.

### 6.3 Fast path

1. Before dispatching to a writer: normalize the prompt and look for an exact `prompt_sha256` hit within the TTL.
2. Otherwise, if Ollama is present (§5): embed the prompt (`nomic-embed-text`, 768-d) and run a cosine top-3 over this project's rows. Threshold ≥ 0.88 (tune).
3. On a hit, prepend ≤ 120 tokens: "Previous similar task (date, writer, exit, files changed, 1-line outcome)". Never auto-skip the task. Budget ≤ 50 ms without embeddings, ≤ 400 ms with.

### 6.4 Redaction before storing

Use `scrubProjectHistorySkillgenSecrets` (`apps/live/features/project-history/internal/core/scrubProjectHistorySkillgenSecrets.ts:13-63`: private keys, `sk-`, GitHub `gh*_`, Slack `xox*`, AWS `AKIA`, Bearer, `api_key=/token=/password=` …, returns `residualSecret`). If `residualSecret` is true, **do not store**. It is stronger than `redactTextForProjectKnowledge` (`apps/live/features/projects/internal/core/knowledge/redactTextForProjectKnowledge.ts:2-8`, emails + `sk-` only), which the RAG uses today.

### 6.5 Schema sketch

```sql
-- PROPOSAL: <profileDir>/project-data/<projectId>/outcomes/outcomes.db  (node:sqlite)
CREATE TABLE IF NOT EXISTS outcome_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS task_outcome (
  id             TEXT PRIMARY KEY,          -- agentRunId
  project_id     TEXT NOT NULL,
  writer_agent   TEXT NOT NULL,             -- claude-cli|codex|cursor|gemini|antigravity
  prompt_sha256  TEXT NOT NULL,
  prompt_summary TEXT NOT NULL,             -- scrubbed, ≤ 500 chars
  outcome        TEXT NOT NULL CHECK (outcome IN ('completed','failed','stopped','timeout')),
  exit_code      INTEGER,
  outcome_summary TEXT NOT NULL,            -- scrubbed, ≤ 800 chars
  files_changed  INTEGER,
  duration_s     INTEGER,
  tokens_total   INTEGER,
  embed_model    TEXT,                      -- e.g. nomic-embed-text@<digest>
  embedding      BLOB,                      -- Float32Array(768) little-endian, nullable
  created_at     TEXT NOT NULL,
  last_hit_at    TEXT
);
CREATE INDEX IF NOT EXISTS task_outcome_prompt_idx ON task_outcome (prompt_sha256);
CREATE INDEX IF NOT EXISTS task_outcome_created_idx ON task_outcome (created_at);
```

### 6.6 Retention

Default 90 days or 2,000 rows per project (whichever comes first), pruned on write. Embeddings are dropped when `embed_model` changes. Everything is purged on History OFF or owner delete. Cross-check with the existing 500-chunk RAG cap (`AGENT_WITCH_PROJECT_RAG_CHUNK_CEILING`).

See `awl-cache-redis.md` (same folder) for vector-store options.
